# JD-009：机器人软件系统开发工程师

> 更新时间：2026-07-09  
> 地点：深圳 / 上海  
> 性质：全职  
> 板块：智能机器人

## 原始 JD 要点

### 工作内容

- 负责人形机器人本体软件系统的设计与开发，将 AI 算法落地为可靠运行的机器人软件。
- 与算法团队协作，把强化学习、VLA、大语言模型等能力集成进机器人系统，开发并优化 C++ 推理管道。
- 设计机器人核心软件架构，包括功能状态机、资源编排、任务调度，支撑机器人自主完成复杂任务。
- 开发高性能中间件，包括通信、监控、日志，保证多模块之间低延迟、高可靠的数据交换。
- 负责机器人数据采集、录制、回放与云端同步，形成数据闭环。
- 参与嵌入式层开发，包括 IMU、摄像头、力传感器和执行器驱动，打通 AI 算法到底层硬件的完整链路。

## 岗位判断

这是偏**机器人本体软件系统 / AI 工程化落地**的核心岗位，比普通 ROS2 应用开发更接近机器人系统架构层。
岗位不只要求会写节点，还要求把推理、通信、状态机、日志、数据闭环和硬件驱动串成可运行的软件系统。

优先级：**主投，但需要把项目表达升级为系统级能力**。

## 与当前背景的匹配度

### 已有优势

- 有 C++ 和 Linux 开发基础，可迁移到系统级软件方向。
- 有机械臂客户端和机器人相关业务背景，容易解释为什么转向本体软件。
- 已经在补 ROS2、IPC、状态机、共享内存、线程池等内容，和岗位关键词高度相关。

### 主要差距

1. **C++17 系统工程深度**：需要能讲清楚线程模型、内存生命周期、性能瓶颈定位、异常与错误码策略。
2. **实时系统经验**：至少要理解 PREEMPT_RT、线程优先级、调度抖动、锁竞争对实时性的影响。
3. **机器人中间件深度**：ROS2 不能只停留在 Topic，需要理解 DDS QoS、生命周期节点、参数、日志与监控。
4. **AI 推理部署链路**：需要至少跑通过 ONNX Runtime 或 TensorRT，把模型输入输出接入 C++ 推理管道。
5. **硬件通信接口**：CAN / EtherCAT / SPI 至少选 CAN 做一个可讲项目，先用 SocketCAN 或虚拟 CAN 起步。
6. **数据闭环**：需要有采集、录制、回放、同步、问题复现的设计意识。

## 学习努力方向

### 第一优先级：做出一个可讲的机器人软件系统

目标不是堆技术名词，而是做一个面试能讲 10 分钟的系统：

```
ROS2 多节点 + 状态机 + C++ 推理服务 + 日志监控 + 数据录制回放 + CAN 模拟驱动
```

建议项目名：**Humanoid Runtime Mini**。

模块拆分：

| 模块 | 训练点 | 简历表达 |
|------|--------|----------|
| 状态机节点 | Idle / Standby / Running / Fault / Recovery | 设计机器人任务状态机与故障恢复流程 |
| 推理节点 | ONNX Runtime C++ 推理，输入模拟传感器数据 | 将 AI 模型封装为低延迟 C++ 推理服务 |
| 通信层 | ROS2 Topic / Service / Action，补 DDS QoS | 优化多模块数据交换的可靠性与延迟 |
| 数据层 | rosbag2 或自定义日志，支持回放 | 建立采集、录制、回放的问题复现链路 |
| 驱动层 | SocketCAN / vcan 模拟执行器状态 | 对接底层总线数据，抽象执行器驱动接口 |
| 监控层 | 日志、心跳、耗时统计 | 定位模块超时、丢包和状态异常 |

### 第二优先级：把 C++17 和 Linux 实时能力补到面试可讲

- C++17：`std::optional`、`std::variant`、`std::string_view`、结构化绑定、`if constexpr`。
- 并发：线程池、条件变量、无锁队列基本思想、生产者消费者、死锁排查。
- 性能：减少拷贝、对象生命周期、内存池基本思想、缓存友好数据结构。
- 实时：PREEMPT_RT 作用、线程优先级、CPU 亲和性、调度延迟、锁对实时线程的影响。
- 工具：`perf`、`htop`、`strace`、`gdb`、`valgrind` 或 `asan`。

### 第三优先级：补 AI 推理部署和硬件接口关键词

先选低成本路径：

- 推理：优先 ONNX Runtime C++，再看 TensorRT。
- 模型：用一个小型 ONNX 模型即可，重点是封装、耗时统计、输入输出校验。
- 硬件：优先 SocketCAN / vcan，能讲 CAN 帧、周期发送、超时检测、故障状态。
- 仿真：先 MuJoCo / Gazebo 二选一，不要一开始同时铺开 MuJoCo、Isaac Gym、Isaac Sim。

## 投递前检查清单

- 能解释机器人软件系统如何从传感器数据流到任务状态机，再到执行器命令。
- 能讲清楚 ROS2 Topic / Service / Action 的使用边界。
- 能说明 DDS QoS 中 reliability、durability、history、deadline 对机器人系统的影响。
- 能用一个例子解释实时线程为什么要避免长时间持锁和动态内存分配。
- 能展示一次数据录制、回放、定位问题的闭环。
- 能把“AI 算法落地”讲成工程链路：模型格式、输入输出、推理耗时、异常处理、版本管理。
