# 工作日 2 小时量化学习计划

目标：把每天可用的 2 小时固定投入到可验证产出上，12 周后形成一套能投递机器人软件系统开发工程师的作品和面试材料。

适用岗位：[JD-009 机器人软件系统开发工程师](/jd/jd_009_robot_software_system_engineer)

## 执行规则

每天 2 小时拆成三段：

| 时间 | 内容 | 要求 |
|------|------|------|
| 20 分钟 | 复盘与笔记 | 写下昨天遗留问题、今天目标、1 个面试解释点 |
| 80 分钟 | 写代码或跑实验 | 必须产生 commit、代码片段、命令记录、截图或日志之一 |
| 20 分钟 | 总结与验收 | 写 3 行总结：完成了什么、卡在哪里、明天做什么 |

每周五做一次验收：

- 至少 1 个可运行 Demo 或可复现实验。
- 至少 1 篇短笔记，能用于面试口述。
- 至少 1 次代码整理，把临时代码变成项目结构。
- 周末不强制学习，只用于补环境、补坑、整理简历表达。

## 12 周主线

| 阶段 | 周次 | 核心目标 | 周产出 |
|------|------|----------|--------|
| 基础系统层 | 第 1-4 周 | C++17、Linux 并发、ROS2 基础、状态机 | 可运行的 ROS2 多节点状态机 Demo |
| 机器人系统层 | 第 5-8 周 | DDS QoS、数据录制回放、推理部署、CAN 模拟驱动 | Humanoid Runtime Mini 骨架 |

## 第 1 周：C++17 与 Linux 并发复盘

目标：把 C++ 系统开发基础补到能写、能讲、能被追问。

| 工作日 | 2 小时任务 | 可量化验收 |
|--------|------------|------------|
| 周一 | 复习 RAII、`unique_ptr`、`shared_ptr`，手写资源管理类 | 1 个 `ResourceGuard` 示例，能解释所有权转移 |
| 周二 | 复习 `std::thread`、`mutex`、`condition_variable` | 1 个生产者消费者队列，跑 1000 条消息不丢 |
| 周三 | 写线程池最小实现 | 线程池支持提交 20 个任务并收集结果 |
| 周四 | 学 C++17：`optional`、`variant`、`string_view` | 每个特性写 1 个机器人场景小例子 |
| 周五 | 整理并发面试笔记 | 1 页笔记：锁、条件变量、死锁、线程池 |

## 第 2 周：ROS2 基础节点与构建系统

目标：能独立创建 ROS2 C++ 包，跑通 Topic / Service / Action 的基本链路。

| 工作日 | 2 小时任务 | 可量化验收 |
|--------|------------|------------|
| 周一 | 创建 ROS2 workspace 和 C++ package | `colcon build` 成功，节点能启动 |
| 周二 | 写传感器发布节点 | 10Hz 发布模拟 IMU / joint state 数据 |
| 周三 | 写状态订阅节点 | 能订阅并打印延迟、序号、时间戳 |
| 周四 | 写 Service：重置状态 / 查询状态 | `ros2 service call` 能返回当前状态 |
| 周五 | 写 Action：执行一个模拟任务 | `ros2 action send_goal` 能看到反馈和结果 |

## 第 3 周：机器人状态机

目标：把机器人任务状态从 if-else 升级为可维护状态机。

| 工作日 | 2 小时任务 | 可量化验收 |
|--------|------------|------------|
| 周一 | 设计状态：Idle / Standby / Running / Fault / Recovery | 画出状态转换表 |
| 周二 | 用 C++ 实现状态机核心类 | 单元或主函数覆盖 8 个状态转换 |
| 周三 | 接入 ROS2 节点 | Topic 或 Service 可触发状态切换 |
| 周四 | 加入错误码和故障恢复 | 模拟超时后进入 Fault，再恢复到 Standby |
| 周五 | 整理状态机面试讲稿 | 1 页笔记：为什么不用散乱 if-else |

## 第 4 周：日志、心跳与监控

目标：让系统具备可观察性，能发现节点是否活着、是否超时。

| 工作日 | 2 小时任务 | 可量化验收 |
|--------|------------|------------|
| 周一 | 设计统一日志字段 | 日志包含时间、节点、状态、错误码、耗时 |
| 周二 | 写心跳发布与订阅 | 3 个节点每秒发布心跳 |
| 周三 | 写 watchdog 监控节点 | 任一节点 3 秒无心跳进入 Fault |
| 周四 | 记录关键耗时 | 输出消息处理耗时、任务执行耗时 |
| 周五 | 第 1 阶段集成验收 | 一条命令启动多节点，能看到状态、日志、心跳 |

## 执行建议

- 工作日只做一件主任务，不同时打开 ROS2、C++、Qt、算法多条线。
- 每天学习结束前必须留下明天第一条命令，降低第二天启动成本。
- 学不会的概念先写成问题，不要当天无限查资料。
- 每周五优先整理成果，周末再补欠账。
- 简历只写自己能现场解释、能展示日志或代码的内容。
