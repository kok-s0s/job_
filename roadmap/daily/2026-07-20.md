### 题目 4：写最小节点

创建文件：

```txt
~/ros2_ws/src/robot_runtime_demo/src/runtime_node.cpp
```

代码：

```cpp
#include <chrono>
#include <memory>

#include "rclcpp/rclcpp.hpp"

using namespace std::chrono_literals;

class RuntimeNode : public rclcpp::Node {
public:
    RuntimeNode()
        : Node("runtime_node") {
        timer_ = create_wall_timer(1s, [this] {
            RCLCPP_INFO(get_logger(), "runtime_node heartbeat");
        });
    }

private:
    rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char** argv) {
    rclcpp::init(argc, argv);
    rclcpp::spin(std::make_shared<RuntimeNode>());
    rclcpp::shutdown();
    return 0;
}
```

修改 `CMakeLists.txt`，加入：

```cmake
add_executable(runtime_node src/runtime_node.cpp)
ament_target_dependencies(runtime_node rclcpp)

install(TARGETS
  runtime_node
  DESTINATION lib/${PROJECT_NAME}
)
```

验收：

- `colcon build --packages-select robot_runtime_demo` 成功。
- `ros2 run robot_runtime_demo runtime_node` 能每秒打印一次 heartbeat。

## ROS2 工程结构笔记

1. workspace 是一组 ROS2 package 的工作目录，通常包含 `src/`、`build/`、`install/`、`log/`。
2. package 是 ROS2 的基本构建和发布单元，里面可以包含一个或多个 node、库、launch 文件和配置文件。
3. node 是运行时进程里的功能单元，`runtime_node` 就是一个最小 C++ 节点。
4. `source /opt/ros/humble/setup.bash` 让当前 shell 获得 ROS2 Humble 的命令、环境变量和基础包路径。
5. `source install/setup.bash` 让当前 shell 能发现当前 workspace 新构建出来的 package。
6. `package.xml` 负责描述包名、版本、维护者、license 和依赖；`CMakeLists.txt` 负责具体怎么编译、链接和安装。
7. `rclcpp::init()` 初始化 ROS2 C++ 客户端库；`rclcpp::shutdown()` 负责退出前清理 ROS2 上下文。

## 常见错误

- 忘记 `source /opt/ros/humble/setup.bash`，导致找不到 `ros2` 或 `rclcpp`。
- 构建后忘记 `source install/setup.bash`，导致 `ros2 run` 找不到新 package。
- `CMakeLists.txt` 里加了 executable，但忘记 `install(TARGETS ...)`。
- package 名、executable 名、`ros2 run` 命令里的名字混淆。
- 在 Mac 上直接执行 ROS2 Humble 命令。当前计划默认在 Windows WSL2 + Ubuntu 22.04 执行。

## 面试表达模板

> ROS2 的基本组织是 workspace 下面放 package，package 里定义一个或多个 node。`package.xml` 描述包的元信息和依赖，`CMakeLists.txt` 负责构建目标、链接依赖和安装可执行文件。构建后要 source workspace 的 `install/setup.bash`，这样当前 shell 才能发现新生成的 package 和可执行节点。
