### 题目 2：封装状态摘要函数

```cpp

```

要求返回内容至少包含：

- `state`
- `imu_count`
- `joint_count`
- `latest_accel_z`
- `latest_joint_count`
- `imu_latency_ms`
- `joint_latency_ms`
- `joint_valid`

建议格式：

```txt
state=RUNNING imu_count=42 joint_count=42 latest_accel_z=9.80 latest_joint_count=3 imu_latency_ms=0.31 joint_latency_ms=0.24 joint_valid=1
```

实现建议：

```cpp
#include <sstream>
```

```cpp
std::string buildStatusSummary() const {
    std::ostringstream oss;
    oss << "state=" << runtime_state_
        << " imu_count=" << imu_count_
        << " joint_count=" << joint_count_
        << " latest_accel_z=" << latest_accel_z_
        << " latest_joint_count=" << latest_joint_count_
        << " imu_latency_ms=" << latest_imu_latency_ms_
        << " joint_latency_ms=" << latest_joint_latency_ms_
        << " joint_valid=" << latest_joint_valid_;
    return oss.str();
}
```

## ROS2 Service 面试笔记

1. Topic 适合连续数据流，例如 IMU、JointState、图像；Service 适合一次性请求/响应，例如查询状态、清故障、加载配置。
2. 状态查询适合 Service，因为调用方只在需要时请求一次快照，不需要长期订阅高频状态流。
3. `std_srvs/srv/Trigger` 的 request 为空，response 包含 `success` 和 `message`，适合“无参数触发并返回结果”的轻量接口。
4. 本 demo 中 `query_status.success` 表达 runtime 当前是否健康：`RUNNING` 返回 `true`，`BOOTING` 或 `FAULT` 返回 `false`。
5. `buildStatusSummary()` 让 heartbeat 和 service 复用同一份状态字段，后续新增指标时只需要改一个地方。

## 常见错误

- service 名称写成 `runtime/query_status` 也能解析，但命令行习惯上用 `/runtime/query_status` 调用。
- callback 里忘记调用 `updateRuntimeState()`，导致查询结果不是最新状态。
- `response->success` 的语义没想清楚：可以表示 service 调用成功，也可以表示 runtime 是否健康，但项目里要保持一致。
- `buildStatusSummary()` 用了 `std::ostringstream`，但忘记 include `<sstream>`。
- 改 heartbeat 时删掉了原本的延迟、计数或 `joint_valid` 字段，导致可观察性退化。
