- `/runtime/query_status`：查询当前状态、错误语义、传感器计数、延迟、任务状态。
- `/runtime/apply_event`：外部通过事件名驱动状态机，并拿到前后状态和故障语义。
- `/runtime/execute_task`：Action 模拟长耗时任务，支持 feedback、result、cancel。
- `verify_ros2_runtime_demo.sh`：一条命令完成 ROS2 全链路验收。

## 面试讲稿模板

> 我做了一个 ROS2 机器人运行时状态机 demo，用来模拟机器人从传感器健康检测、任务执行、故障进入到恢复的完整流程。系统里有一个 `sensor_sim_node` 以 10Hz 发布 IMU 和 JointState，`runtime_node` 订阅这些 Topic，并把传感器健康、任务开始、任务完成、故障复位等输入转换成状态机事件。状态机核心是纯 C++ 的 `RuntimeStateMachine`，不依赖 ROS2，所以可以单独编译和验证；ROS2 层只负责通信和事件适配。
>
> 状态设计为 `Idle / Standby / Running / Fault / Recovery`。外部不能直接指定目标状态，只能发送事件，例如 `SensorTimeout`、`StartTask`、`ResetFault`，由状态机决定当前状态下这个事件是否合法。进入故障后不会自动回到待命，而是必须经过 `ResetFault -> RecoveryDone`，这样能避免故障被传感器恢复信号悄悄掩盖。
>
> 我还给错误码增加了工程语义：每个错误码都有 severity、recoverable、reason 和 recovery_hint。`/runtime/query_status` 能返回当前状态、错误码、严重级别、恢复建议、传感器计数和延迟；`/runtime/apply_event` 能让调试脚本通过事件驱动状态切换，并看到切换前后状态。长耗时任务用 Action 实现，支持 feedback、result 和 cancel，不阻塞 heartbeat 与查询服务。
>
> 最终验收是一条脚本完成：`colcon build`、状态机 demo、Topic echo/hz、query/reset/apply_event service、Action 正常完成、非法 goal 拒绝和主动取消。这个 demo 展示的不只是 ROS2 API 用法，而是一个可观测、可恢复、可测试的机器人运行时骨架。
