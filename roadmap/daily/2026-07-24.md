### 题目 1：创建自定义 Action 接口

在 package 中新增：

```txt
projects/ros2_runtime_demo/src/robot_runtime_demo/action/ExecuteTask.action
```

接口内容：

```action
int32 target_steps
---
bool success
string message
---
int32 current_step
float32 progress
```

要求：

- `target_steps` 必须大于 0。
- feedback 的 `progress` 范围为 `0.0` 到 `1.0`。
- result 能区分完成、取消和失败。
- 在 `CMakeLists.txt` 与 `package.xml` 中补齐 Action 接口生成依赖。

提示依赖：

```txt
action_msgs
rosidl_default_generators
rosidl_default_runtime
```

### 题目 2：实现 Action server

在 `runtime_node.cpp` 中创建：

```txt
/runtime/execute_task
```

建议拆成 3 个处理函数：

```cpp
handleGoal(...)
handleCancel(...)
handleAccepted(...)
```

要求：

- 非法 goal（`target_steps <= 0`）返回 reject。
- 合法 goal 返回 accept。
- 允许客户端取消任务。
- 执行过程不能阻塞 ROS2 executor 的其他 callback。
- 每完成一步发布一次 feedback。
- 每一步休眠约 200 ms，方便观察进度。

建议先画出控制流程：

```txt
收到 goal
  → 校验 target_steps
  → 接受并启动执行线程
  → 循环检查 cancel
  → 发布 feedback
  → succeed / canceled
```

### 题目 3：处理完成与取消

执行循环至少覆盖以下 3 条路径：

1. 正常完成：调用 `goal_handle->succeed(result)`。
2. 客户端取消：调用 `goal_handle->canceled(result)`。
3. 节点停止：安全退出执行逻辑，不留下失控线程。

正常完成时，result 建议返回：

```txt
success=true
message="task completed"
```

取消时，result 建议返回：

```txt
success=false
message="task canceled at step N"
```

额外挑战：

- 执行期间把 runtime 状态改为 `RUNNING`。
- 任务完成或取消后恢复为 `IDLE`。
- 同一时刻只允许一个 active goal。

## Topic / Service / Action 对比笔记

1. Topic 是持续、异步的数据流，发布者不等待订阅者响应，适合 IMU、关节状态等周期数据。
2. Service 是一次请求对应一次响应，适合快速完成的状态查询、复位或配置操作。
3. Action 面向持续一段时间的目标，除最终 result 外还能发送 feedback，并支持 cancel。
4. 长任务若直接占用 Service callback，会延迟同一 executor 中的 heartbeat 和其他请求；Action 执行应与回调接收解耦。
5. Action 的 goal 表达“想完成什么”，feedback 表达“进行到哪里”，result 表达“最终是否完成以及为什么”。

## 思考题答案

1. 10 秒任务需要持续进度和取消能力，Service 只有一次请求/响应，无法自然表达中间反馈和目标生命周期。
2. `handleAccepted` 属于 executor 回调；直接执行耗时循环会占住执行线程，使同 executor 的 Timer、Topic 和 Service 延迟。
3. goal 是目标参数，feedback 是过程状态，result 是终态与业务结果。
4. cancel callback 只表示 server 接受取消请求，执行线程仍需在安全点检查 `is_canceling()`，才能停止业务动作并返回 canceled result。
5. 当前策略是同一时间只允许一个 active goal；原子占用失败时拒绝新 goal，避免两个任务同时修改运行状态。
