### 题目 2：设计统一日志字段表

把今日日志字段整理成一张表：

| 字段 | 类型 | 示例 | 作用 |
|------|------|------|------|
| `timestamp_ms` | integer | `1785748800123` | 定位事件发生时间 |
| `node` | string | `runtime_node` | 知道是哪一个节点输出 |
| `level` | string | `INFO/WARN/ERROR` | 快速筛选严重程度 |
| `event` | string | `heartbeat/state_transition/service_call` | 区分日志类型 |
| `state` | string | `STANDBY/FAULT/RUNNING` | 观察运行时状态 |
| `runtime_error` | string | `NONE/SENSOR_TIMEOUT` | 定位故障类别 |
| `severity` | string | `INFO/WARNING/CRITICAL` | 判断处理优先级 |
| `recoverable` | bool | `true/false` | 判断是否能自动恢复 |
| `latency_ms` | number | `12.4` | 观察数据或处理延迟 |
| `duration_ms` | number | `200.0` | 观察任务或回调耗时 |
| `message` | string | `runtime healthy` | 给人看的短说明 |

验收：字段表必须能覆盖 heartbeat、故障、Service 调用、Action 执行四类日志。

### 题目 3：写 3 条标准日志样例

按下面格式写 3 条样例，并让 ROS2 demo 输出同类字段：

```txt
[runtime_log] ts=1785748800123 node=runtime_node level=INFO event=heartbeat state=STANDBY runtime_error=NONE severity=INFO recoverable=1 latency_ms=8.2 duration_ms=0.3 message="runtime healthy"
[runtime_log] ts=1785748802123 node=runtime_node level=ERROR event=state_transition state=FAULT runtime_error=SENSOR_TIMEOUT severity=CRITICAL recoverable=1 latency_ms=3050.5 duration_ms=0.1 message="sensor heartbeat timeout"
[runtime_log] ts=1785748804123 node=runtime_node level=INFO event=service_call state=RECOVERY runtime_error=NONE severity=INFO recoverable=1 latency_ms=0.0 duration_ms=1.4 message="reset_fault accepted"
```

验收：每条日志都必须能回答三个问题：

1. 哪个节点在什么时间发生了什么？
2. 当前状态和错误是什么？
3. 这件事是否严重、是否可恢复、耗时多少？

### 题目 4：解释日志字段的实际意义

用 5 句话解释这件事的工程价值：

```md
1. 统一日志字段可以让人和脚本用同一套方式理解系统状态。
2. heartbeat 日志告诉我们节点是否还活着、数据是否还在更新。
3. 故障日志把错误码、严重级别和恢复建议放在一起，减少现场排障成本。
4. duration_ms 和 latency_ms 能帮助判断问题是通信延迟、回调阻塞还是任务执行太慢。
5. 后续 watchdog 和监控 UI 不需要重新猜字段，只要消费这套日志即可。
```

验收：能说清楚“日志不是打印给自己看的，而是给后续监控、脚本和排障流程看的”。

## 已实现内容

- `runtime_node.cpp`：新增统一日志构造函数，输出 `[runtime_log] ts=... node=runtime_node level=... event=... state=... runtime_error=... severity=... recoverable=... latency_ms=... duration_ms=... message="..."`。
- heartbeat：每秒输出 `event=heartbeat`，携带状态、错误语义、最大传感器延迟和回调耗时。
- 状态切换：状态机迁移输出 `event=state_transition`，保留 `runtime transition A --Event--> B error=X` 的可读信息。
- Service：`query_status`、`reset_fault`、`apply_event` 输出 `event=service_call`，方便脚本和后续 UI 追踪外部控制入口。
- Action：goal、cancel、feedback、result 分别输出 `event=action_goal/action_cancel/action_feedback/action_result`，方便定位长耗时任务进度和取消路径。
- `verify_ros2_runtime_demo.sh`：新增结构化日志字段 grep，确认 heartbeat、状态切换、Service 和 Action 日志稳定出现。
