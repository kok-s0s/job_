# 2026-08-24 准备一个小 ONNX 模型

## 今日目标

进入第 7 周 ONNX Runtime C++ 推理部署主题。今天先准备一个足够小、足够稳定的 ONNX 模型，重点确认输入输出名字和 shape。

## 已完成内容

- 新增 `projects/onnx_runtime_cpp_demo` 项目目录。
- 新增 `scripts/create_tiny_robot_score_onnx.py`，用纯 Python 标准库生成最小 ONNX protobuf。
- 生成模型 `models/tiny_robot_score.onnx`。
- 模型输入为 `robot_features`，shape 为 `[1,3]`。
- 模型输出为 `anomaly_score`，shape 为 `[1,1]`。

## 模型结构

```txt
robot_features[1,3]
  -> MatMul(score_weight[3,1])
  -> Add(score_bias[1])
  -> anomaly_score[1,1]
```

## 验收命令

```bash
cd projects/onnx_runtime_cpp_demo
python3 scripts/create_tiny_robot_score_onnx.py --output models/tiny_robot_score.onnx
```

关键输出：

```txt
[ok] wrote models/tiny_robot_score.onnx bytes=...
[model] input=robot_features shape=[1,3] output=anomaly_score shape=[1,1] opset=13
```

## 复盘要点

- 小模型的价值是稳定：可以先验证工程链路，再替换真实算法模型。
- 推理部署前必须先明确模型契约：输入名、输出名、shape、数据类型和 opset。
- 机器人项目里输入可以对应传感器/状态特征，输出可以对应异常分数、分类结果或控制辅助量。
