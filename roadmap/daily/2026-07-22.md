### 题目 2：计算订阅延迟

在 IMU callback 中：

- 收到消息时记录 `const auto received_at = now();`
- 用 `msg->header.stamp` 和 `received_at` 计算延迟。
- 日志打印 `latency_ms`。

在 JointState callback 中做同样的事。

建议辅助函数：

```cpp
double latencyMs(const builtin_interfaces::msg::Time& stamp) const {
    const rclcpp::Time sent_at(stamp);
    return (now() - sent_at).seconds() * 1000.0;
}
```

验收日志应包含：

```txt
imu latency_ms=...
joint_states latency_ms=...
```

### 题目 4：加入 topic 超时健康检查

在 1Hz heartbeat timer 中检查：

- 如果还没收到 IMU 或 JointState，状态保持 `BOOTING`。
- 如果任一 topic 超过 1 秒没更新，状态置为 `FAULT`。
- 如果两个 topic 都正常更新，且 JointState 形状正确，状态置为 `RUNNING`。

建议拆一个函数：

```cpp
void updateRuntimeState() {
    if (imu_count_ == 0 || joint_count_ == 0) {
        runtime_state_ = "BOOTING";
        return;
    }

    const auto current_time = now();
    const bool imu_timeout = (current_time - last_imu_time_).seconds() > 1.0;
    const bool joint_timeout = (current_time - last_joint_time_).seconds() > 1.0;

    runtime_state_ = (!imu_timeout && !joint_timeout && latest_joint_valid_)
        ? "RUNNING"
        : "FAULT";
}
```

验收 heartbeat 日志应包含：

```txt
runtime status=RUNNING imu_received=... joint_received=... imu_latency_ms=... joint_latency_ms=... joint_valid=1
```

## ROS2 Subscriber 面试笔记

1. subscriber callback 是运行时系统的数据入口，适合做轻量解析、计数、时间戳记录和状态更新，耗时任务应拆到独立线程或任务队列。
2. `Header.stamp` 表示消息生成或发布时刻，订阅端可以用它计算接收延迟，定位通信阻塞、调度抖动或发布端异常。
3. topic 频率说明数据是否按预期持续到达，接收延迟说明数据从生成到被处理花了多久，两者观察的问题不同。
4. `JointState` 的 `name`、`position`、`velocity` 是按下标一一对应的数组，长度不一致会让订阅端无法判断哪个值属于哪个关节。
5. 机器人运行时不能只关心进程是否活着，还要关心关键 topic 是否持续更新；传感器断流通常应该进入故障或降级状态。

## 常见错误

- 用 `now()` 当发送时间，导致延迟永远接近 0，忘了消息里的 `header.stamp` 才是发送端时间。
- `rclcpp::Time` 没有从 `msg->header.stamp` 构造，直接做类型不匹配的减法。
- 只检查 topic 是否存在，没检查消息是否持续更新。
- JointState 只看 `name.size()`，忘记 `position` 和 `velocity` 也要等长。
- heartbeat 日志字段太少，运行时出问题时看不出是 IMU 断了还是 JointState 断了。

## 面试表达模板

> 我会把运行时节点做成状态订阅和健康检查中心。传感器节点发布带 `Header.stamp` 的 typed message，运行时订阅后用当前时间减发送时间得到接收延迟，同时统计消息计数和最近更新时间。如果某个 topic 超过阈值没有更新，或者 JointState 的数组形状不一致，就把运行状态置为 Fault。这样不仅能证明通信链路通了，也能对实时性和数据质量做基本观察。
