## 代码骨架

```cpp
#include <chrono>
#include <condition_variable>
#include <functional>
#include <iostream>
#include <mutex>
#include <queue>
#include <thread>
#include <vector>

class ThreadPool {
public:
    explicit ThreadPool(std::size_t worker_count) {
        for (std::size_t i = 0; i < worker_count; ++i) {
            workers_.emplace_back([this, i] {
                workerLoop(i);
            });
        }
    }

    ~ThreadPool() {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            stopped_ = true;
        }
        cv_.notify_all();

        for (auto& worker : workers_) {
            if (worker.joinable()) {
                worker.join();
            }
        }
    }

    ThreadPool(const ThreadPool&) = delete;
    ThreadPool& operator=(const ThreadPool&) = delete;

    void submit(std::function<void()> task) {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            if (stopped_) {
                return;
            }
            tasks_.push(std::move(task));
        }
        cv_.notify_one();
    }

private:
    void workerLoop(std::size_t worker_id) {
        (void)worker_id;

        while (true) {
            std::function<void()> task;
            {
                std::unique_lock<std::mutex> lock(mutex_);
                cv_.wait(lock, [this] {
                    return stopped_ || !tasks_.empty();
                });

                if (stopped_ && tasks_.empty()) {
                    return;
                }

                task = std::move(tasks_.front());
                tasks_.pop();
            }

            task();
        }
    }

    std::vector<std::thread> workers_;
    std::queue<std::function<void()>> tasks_;
    std::mutex mutex_;
    std::condition_variable cv_;
    bool stopped_{false};
};

int main() {
    constexpr std::size_t worker_count = 4;
    constexpr int task_count = 20;

    std::vector<int> results(task_count, -1);
    std::mutex result_mutex;
    int completed = 0;

    {
        ThreadPool pool(worker_count);

        for (int i = 0; i < task_count; ++i) {
            pool.submit([i, &results, &result_mutex, &completed] {
                std::this_thread::sleep_for(std::chrono::milliseconds(5));
                const int value = i * i;
                {
                    std::lock_guard<std::mutex> lock(result_mutex);
                    results[i] = value;
                    ++completed;
                }
            });
        }
    }

    int sum = 0;
    bool values_ok = true;
    for (int i = 0; i < task_count; ++i) {
        sum += results[i];
        values_ok = values_ok && results[i] == i * i;
    }

    const bool pass = completed == task_count && values_ok && sum == 2470;

    std::cout << "worker_count: " << worker_count << '\n';
    std::cout << "task_count: " << task_count << '\n';
    std::cout << "completed: " << completed << '\n';
    std::cout << "sum: " << sum << '\n';
    std::cout << "result: " << (pass ? "pass" : "fail") << '\n';

    return pass ? 0 : 1;
}
```

## 线程池面试笔记

1. 线程池复用固定 worker，避免每个任务都创建线程，适合日志处理、传感器后处理、异步 IO 回调等系统任务。
2. 任务队列是共享资源，提交任务和 worker 取任务都必须加锁。
3. worker 使用 `wait(lock, predicate)`，谓词检查“已停止”或“队列非空”，避免虚假唤醒后读空队列。
4. worker 不能看到 `stopped_` 就立刻退出，必须等到 `stopped_ && tasks_.empty()`，否则会丢弃已提交任务。
5. 执行 `task()` 前必须释放队列锁，否则多个 worker 会因为同一把锁被串行化。
6. 析构函数必须 `join()` 所有 worker，否则线程对象析构会触发 `std::terminate`，或者留下后台线程访问已销毁对象。
7. 真实工程里要明确线程池生命周期：停止后不再允许业务层继续 `submit()`，通常通过上层状态机或 `stop()` 接口约束。

## 常见错误

- 析构时只设置 `stopped_`，但忘记 `notify_all()`，worker 可能永远睡眠。
- worker 一看到 `stopped_` 就退出，导致队列里剩余任务被丢弃。
- 在持锁状态下执行 `task()`，会导致所有 worker 串行化。
- `completed` 被多个任务同时写却不加锁，产生数据竞争。
- `ThreadPool` 析构前任务还没执行完，但主线程提前读取结果。

## 面试表达模板

> 线程池的核心是复用固定数量的 worker，避免每个任务都创建和销毁线程。任务进入共享队列后，worker 用 condition_variable 等待任务到来。取任务时需要加锁，执行任务前要释放锁，否则 worker 会被串行化。析构时先设置停止标志，再 notify_all 唤醒所有 worker；worker 只有在 stopped 且任务队列为空时退出，这样可以保证已提交任务执行完。
