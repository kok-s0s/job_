修改：

```txt
projects/ros2_runtime_demo/src/robot_runtime_demo/src/sensor_sim_node.cpp
```

要求：

- include `sensor_msgs/msg/imu.hpp`
- include `sensor_msgs/msg/joint_state.hpp`
- 创建两个 publisher：
  - `imu_pub_`
  - `joint_pub_`
- timer 周期为 `100ms`。
- IMU 的 `header.stamp` 使用 `now()`。
- IMU 的 `header.frame_id` 使用 `imu_link`。
- JointState 的 `header.stamp` 使用同一个时间戳。
- JointState 的 `name` 至少包含：
  - `joint_1`
  - `joint_2`
  - `joint_3`
- JointState 的 `position`、`velocity` 长度与 `name` 一致。

建议核心代码：

```cpp
void publishSensors() {
    ++sequence_;
    const auto stamp = now();
    const double t = static_cast<double>(sequence_) * 0.1;

    sensor_msgs::msg::Imu imu;
    imu.header.stamp = stamp;
    imu.header.frame_id = "imu_link";
    imu.linear_acceleration.x = 0.1 * std::sin(t);
    imu.linear_acceleration.y = 0.1 * std::cos(t);
    imu.linear_acceleration.z = 9.8;
    imu.angular_velocity.z = 0.05 * std::sin(t);
    imu.orientation.w = 1.0;

    sensor_msgs::msg::JointState joints;
    joints.header.stamp = stamp;
    joints.name = {"joint_1", "joint_2", "joint_3"};
    joints.position = {
        0.5 * std::sin(t),
        0.25 * std::cos(t),
        0.1 * std::sin(0.5 * t),
    };
    joints.velocity = {
        0.5 * std::cos(t),
        -0.25 * std::sin(t),
        0.05 * std::cos(0.5 * t),
    };

    imu_pub_->publish(imu);
    joint_pub_->publish(joints);
}
```

## ROS2 Publisher 面试笔记

1. 传感器数据应优先使用标准 typed message，例如 IMU 用 `sensor_msgs/msg/Imu`，关节状态用 `sensor_msgs/msg/JointState`。
2. `Header.stamp` 记录数据产生或发布的时间，订阅端可以用它计算延迟和做时间同步。
3. `Header.frame_id` 表示数据所属坐标系，例如 IMU 数据来自 `imu_link`。
4. `create_publisher<T>(topic, queue_depth)` 的 `queue_depth` 是发布队列深度，订阅端处理慢时会影响缓存和丢弃策略。
5. 10Hz 对应 100ms timer 周期，但实际频率要用 `ros2 topic hz` 验证。
6. `ros2 topic echo` 验证消息内容，`ros2 topic hz` 验证发布频率。

## 常见错误

- `package.xml` 加了 `sensor_msgs`，但 `CMakeLists.txt` 忘记 `find_package(sensor_msgs REQUIRED)`。
- `ament_target_dependencies(sensor_sim_node ...)` 里忘记加 `sensor_msgs`。
- JointState 的 `name`、`position`、`velocity` 数组长度不一致。
- 没有填 `header.stamp`，后续订阅节点无法计算延迟。
- topic 名一会儿写 `robot/imu`，一会儿写 `/robot/imu`，检查时混淆。

## 面试表达模板

> ROS2 里传感器数据应该优先使用标准 typed message，而不是把所有字段拼成字符串。IMU 用 `sensor_msgs/msg/Imu`，关节状态用 `sensor_msgs/msg/JointState`。每条消息需要带时间戳，后续订阅节点才能计算延迟和同步数据。发布频率可以用 wall timer 控制，10Hz 对应 100ms 周期，再用 `ros2 topic hz` 验证实际发布频率。
