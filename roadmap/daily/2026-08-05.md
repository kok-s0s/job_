今天把这张表升级成 watchdog：**任一节点 3 秒无心跳，就判定 TIMEOUT，并通过 `/runtime/apply_event` Service 触发 `SensorTimeout`，让 runtime_node 进入 Fault**。

## 练习题

### 题目 1：watchdog 的判定规则

写出 watchdog 的核心判定逻辑：

```txt
if now_ms - last_stamp_ms > 3000:
    node_status = TIMEOUT
    trigger SensorTimeout event -> runtime_node enters FAULT
```

验收：能解释为什么用 `now_ms - last_stamp_ms` 而不是 `seq` 是否连续来判断超时（seq 可能因为丢包不连续，但时间戳能反映真实延迟）。

### 题目 2：启动宽限期

为什么 watchdog 需要宽限期？

```txt
节点刚启动，还没收到任何心跳时，状态是 UNKNOWN，不要立刻 Fault。
否则刚启动时 watchdog 会误报所有节点超时。
```

验收：能解释"宽限期"解决的是"冷启动误报"问题。

### 题目 3：watchdog 如何触发 Fault

watchdog 是独立节点，不能直接改 `runtime_node` 的私有状态机。它通过调用 `/runtime/apply_event` Service 发送 `SensorTimeout` 事件，让 runtime_node 自己进入 Fault。

```txt
watchdog_node --(Service call: apply_event SensorTimeout)--> runtime_node -> FAULT
```

验收：能解释为什么用 Service 而不是直接改状态（解耦、复用状态机、可审计）。

### 题目 4：画出今天的节点关系

## WSL2 验证结果（2026-08-05）

在 WSL2（ROS2 Jazzy）中实际编译并运行验证：

**正常心跳场景**：3 个节点均判定 `status=OK`，`age_ms` 稳定在 ~990ms（心跳周期 1s），`last_seq` 递增正常。

```txt
[watchdog] node=heartbeat_monitor_node status=OK age_ms=995 last_seq=1
[watchdog] node=runtime_node status=OK age_ms=962 last_seq=1
[watchdog] node=sensor_sim_node status=OK age_ms=990 last_seq=1
```

**超时 Fault 场景**：杀掉 `sensor_sim_node` 后，其 `age_ms` 从 990 → 1990 → 2990 → 3990 递增，超过 3000ms 阈值后判定 `TIMEOUT`，并成功触发 Fault：

```txt
[WARN] [watchdog] node=sensor_sim_node status=TIMEOUT age_ms=3990 last_seq=3
[WARN] [watchdog] fault triggered accepted=1 transitioned=0 current_state=FAULT error=SENSOR_TIMEOUT
```

说明：`transitioned=0` 是因为 `runtime_node` 自己也检测到了传感器超时（`SENSOR_TIMEOUT`），已先进入 FAULT，watchdog 的触发是冗余安全兜底，符合设计预期。其余节点（`heartbeat_monitor_node`、`runtime_node`）持续 `status=OK`，不受影响。

测试脚本：`scripts/test_watchdog_timeout.sh`（可复现超时场景）。

## 面试表达

可以这样讲：

```md
我把机器人运行时的可观测性分成三层：日志、心跳和 watchdog。日志用于复盘事件，心跳用于周期性证明节点还活着，watchdog 订阅心跳并在超时时触发故障处理。watchdog 的核心是维护每个节点最后一次心跳时间，用 `now_ms - last_stamp_ms` 判断是否超时，而不是看 seq 是否连续，因为时间戳能反映真实延迟。watchdog 需要启动宽限期，否则刚启动时所有节点还没发心跳会误报。当任一节点 3 秒无心跳，watchdog 通过调用 `/runtime/apply_event` Service 发送 `SensorTimeout` 事件，让 runtime_node 自己进入 Fault，这样 watchdog 和 runtime 解耦，状态转换逻辑复用状态机，且每次触发都可审计。
```
