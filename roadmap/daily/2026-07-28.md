### 题目 2：实现 `RuntimeStateMachine`

建议接口：

```cpp
class RuntimeStateMachine {
public:
    RuntimeState state() const;
    RuntimeError error() const;
    bool process(RuntimeEvent event);
    void reset(RuntimeState state = RuntimeState::Idle);
};
```

要求：

- `process()` 返回 `true` 表示发生了状态转换。
- 无效事件返回 `false`，不要修改状态。
- `Fault` 只能通过 `ResetFault` 进入 `Recovery`。
- `Recovery` 只有 `RecoveryDone` 才能回到 `Standby`。
- 转换时同步更新 `RuntimeError`。

验收：

```bash

grep -n "bool process" projects/ros2_runtime_demo/src/robot_runtime_demo/src/runtime_state_machine.hpp
```

## 常见错误

- 继续把状态写成字符串，导致编译期无法检查拼写错误。
- 把 ROS2 header 引入状态机核心类，导致单元测试也必须依赖 ROS2。
- `Fault` 状态收到 `SensorHealthy` 就直接回 `Standby`，绕过 reset/recovery。
- demo 只测正常路径，没有测故障和无效事件。
- CMake 加了可执行文件，但忘记 `install(TARGETS ...)`，导致 `ros2 run` 找不到。

## 面试表达模板

> 我会把机器人运行时状态机做成纯 C++ 核心类，再由 ROS2 node 把 Topic、Service、Action 回调转换成事件喂给它。这样状态转换本身可以脱离 ROS2 单独测试，测试覆盖 Idle、Standby、Running、Fault、Recovery 的关键路径；ROS2 层只负责通信和事件适配。这种拆分能避免状态逻辑散落在 callback 里，也方便后续接入更多节点或 UI。
